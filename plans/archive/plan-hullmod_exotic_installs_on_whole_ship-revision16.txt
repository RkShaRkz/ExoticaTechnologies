REVISION 16 - CHILD FLOW OWNS THE FULL VARIANT GRAPH (ORCHESTRATE, DON'T RELOCATE)
==================================================================================

STATUS: IMPLEMENTED (build-mode). Decisions locked via Q&A.
BASELINE: revision 15 shipped the graph-enumerated ET_MODMAP purge (TEST_RESULTS10
  forensics). Rev-16 is the consolidation pass the user asked for: make the Handler flows

-----------------------------------------------------------------------
0. ORCHESTRATION ANALYSIS (what this revision changes and why)
-----------------------------------------------------------------------
- The install flow ALREADY computed wholeVariantGraph = getWholeVariantGraph(fleetMember)
  internally. What made it asymmetric was that it removed BOTH the campaign root AND the
  refit root (isFromRefitScreen) from childModuleVariants - so the refit root's hullmod was
  only ever poured by HullmodExotic.pourClonePermaMods, outside the flow's bookkeeping.
- The user asked HOW extra graphs should be folded into the flows. Q&A answer:
  "Child flow owns full graph". The child for-loop is the SINGLE install surface for every
  graph in the ship; CheckAndInstallOnMemberModule keeps only the campaign root + the
  bookkeeping seeding. This is orchestration between HullmodExotic and the Handler, NOT a
  code relocation (user's explicit direction).
- Remove side mirrors it: the child remove flow no longer skips the refit root, so it
  reaches every variant that listOfVariantsWeInstalledOn records - the identical full-graph
  set the install flow wrote.
