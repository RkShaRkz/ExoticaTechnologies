2. CHANGE A - ANCHOR RESOLUTION (fixes the broken variant; user-corrected)
----------------------------------------------------------------------------
Replace the fuzzy walk with a null-safe owner-root resolver. Correctness rules:
  - Primary anchor: find the fleetData member whose id == RefitButtonAdder.getRootMember().id.
    Search the sector's fleetData(s) (safe superset), NOT the child FMAPI's own .fleetData
    (transient/zero). Exactly one passes -> deterministic, no cross-ship.
  - If getRootMember() is null (refit closed) -> return null, caller does ZERO whole-ship work
    (never fall back to firstMember -- a child FMAPI's id reshuffles each query).
  - If no fleetData member matches -> return null (fail-safe), caller does zero whole-ship work.

Proposed API (FleetMemberUtils.kt):
    @JvmStatic fun resolveWholeShipRootMember(): FleetMemberAPI? {
        val refitRoot = RefitButtonAdder.getRootMember() ?: return null
        val targetId = refitRoot.id
        // search across the sector's fleets for exactly one member whose id == targetId
        for (fleet in Global.getSector().allFleets) {
            val hit = fleet.fleetData.membersWithFightersCopy
                .asSequence().map { it } // stable id read once
                .firstOrNull { it.id == targetId }
            if (hit != null) return hit
        }
        return null
    }
  NOTE: read .id ONCE into targetId; never re-query a possibly-transient member's id after a
  graph walk. If RefitButtonAdder caches its own root member instance for the refit session,
  prefer iterating from that cached root's fleetData before falling back to sector search.
