1. STRATEGY (user-confirmed via Q&A)
-----------------------------------------------------------------------
- ONE fix: on whole-ship uninstall, enumerate THIS ship's member ids FROM THE GRAPH
  (rootMember.id + FleetMemberUtils.findModuleMember(variant) per getWholeVariantGraph variant)
  and purge this exotic from shipModificationMap under every such id.
- Semantics choice (user-selected): "Enumerate member ids from the graph" over reverse-resolving
  map keys. findModuleMember resolves child FMs + refit/display transients via exact stats
  identity, so the other ship's identical-but-different instance cannot bleed across (the
  twin's member ids are never enumerated for this ship).
- Scope choice (user-selected): "Only ship the ET_MODMAP purge" - do NOT touch ExoticaTechHM,
  do NOT add a probe.
- Explicitly NOT touched (prior rejections stand): shouldInstallHullmodExoticToVariant (no
  presence-guard; LENIENT design must pass), AlphaSubcore, DaemonCore, ExoticaTechHM.java,
  handler Flows, further diagnostic tail-chasing.

2. CHANGE 1 - ET_MODMAP PURGE UNDER GRAPH-ENUMERATED MEMBER IDS (HullmodExotic.kt)
-----------------------------------------------------------------------
- removeExoticDataAcrossShipGraphs (HullmodExotic.kt:220-246), AFTER the rev-14 per-variant
  remove-then-set loop, now does:
    1) val wholeGraphVariants = getWholeVariantGraph(rootMember)   (cached once)
    2) memberIds = LinkedHashSet seeded with rootMember.id; for each graph variant,
       FleetMemberUtils.findModuleMember(variant)?.let { memberIds.add(it.id) }
    3) for each memberId: val stored = PersistentDataProvider.inst.getFromId(memberId)
       ?: continue; if (stored.removeExotic(this)) {
            if (stored.hasAnyModifications()) shipModificationMap[memberId] = stored
            else shipModificationMap.remove(memberId) }
- Direct map writes (bypass PersistentDataProvider.set(), which throws) are the established
  legitimate write path (same map the provider reads). removeExotic on a member that never had
  the exotic is a no-op. Other co-installed exotics and bandwidth of the same member survive
  (hasAnyModifications gate).
- Added import: exoticatechnologies.modifications.PersistentDataProvider. NO new comments; no
  elvis/!!; existing CHANGE A anchor, four remove-flows, stripClonePermaMods,
  refreshStatsEffectsAcrossShipGraphs(apply=false): unchanged.
