## 2. Objective
A per-(ship,module) variant-tag cache served by the write path: writes reach ALL
FleetMemberAPI instances holding the same ship/root, purging stale mirrors at the source
instead of recovering them on read. Cache-scoped only; off-topic findings moved to
plan-sfhs_investigation.txt.
Contract: get() returns null only when there is genuinely no data for that variant (no
hullmod / no exotica). For any multi-module ship our code runs on, children resolve their
OWN ShipModifications (their durable tag, possibly empty), NEVER null. Never fabricate an
in-place empty ShipModifications() when null is the correct answer.

## 6. Decisions
- D1: write-TTL eviction (2 game days) over counter-based nuking. Counters mispredict
  access patterns; TTL bounds staleness absolutely.
- D2: effective shelf life ~3 game days (float 2.9 floors to 2). Eviction fires on a
  1000-read sweep; a cold branch can hold entries past nominal TTL. ACCEPTED: keep the Long
  comparison for speed; TTL just needs to be "short". Do NOT switch to float.
- D3: invalidate across ALL members on write (exact + prefix) rather than lazy invalidation
  on read. Single owner of truth at write time.
- D4: Path B / read-side recovery abandoned — writes prevent the failure class.
- D5: refit/fleet = pure readers (bypass) — keeps the TTL backstop honest.
- D6: write-through applied to member tree + resolved root tree + refit display tree — all
  three are distinct FleetMemberAPI instances serving reads.
- D7: cache keyed by member identity; memory bounded by TTL eviction; no unbounded growth
  across combat/campaign transitions. No capacity backstop needed.
